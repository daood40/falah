# HADITH_API — خادم بيانات الحديث (backend/)

مرجع مختصر؛ التفصيل في `backend/README.md` وعقد الواجهة في `backend/openapi.yaml`.

## الموضع من المشروع

طبقة مستقلة داخل المستودع (`backend/`) تخدم تطبيق Flutter (وPWA لاحقًا) من مخطط
`corpus` في نفس قاعدة بيانات Supabase. لا تمسّ جداول التطبيق في `public`.

## الأمن (SECURITY)

| الطبقة | الإجراء |
|---|---|
| النقل | HTTPS عند النشر؛ ترويسات `nosniff`/`DENY`/`CSP: default-src 'none'`/`no-referrer` |
| المصادقة | عام بلا مفاتيح (قراءة فقط) · إداري: JWT HS256 من Supabase + دور، أو `ADMIN_API_KEY` |
| التفويض | RLS مفعّل على كل جداول `corpus`؛ لا سياسة كتابة واحدة لـ`anon/authenticated` |
| الأسرار | `SUPABASE_SERVICE_ROLE_KEY` خادميًا فقط؛ لا يظهر في ردّ ولا سجلّ ولا في Flutter |
| الإدخال | تحقق صارم من UUID/الأعداد/القوائم المغلقة؛ كل استعلام SQL بمعاملات، بلا تركيب نصي |
| المعدّل | نافذة زمنية لكل IP مع `Retry-After` و429 بغلاف الخطأ الموحّد |
| الأخطاء | لا SQL ولا أثر مكدّس ولا بيانات اتصال في أي ردّ؛ `request_id` فقط للتتبّع |
| التدقيق | `corpus.audit_logs` لكل عملية إدارية واستيراد |
| النص الشرعي | `source_locked` + مشغّلات ترفض التعديل والحذف حتى من المسار الإداري |

## حالة الحقوق

`CONTENT_LICENSE_CONFIRMED=false` افتراضيًا. عندها الـAPI العام يُرجع
`raw_text/matn/isnad/takhrij = null` مع `text_available: false`، ويبقى الوصول
الداخلي بالصلاحية الإدارية. التفعيل بعد تأكيد الحقوق: متغيّر بيئة + صف في
`corpus.app_settings`، بلا إعادة بناء.

## Known limitations

1. **الترخيص غير مؤكد.** الطبعة مستوردة (15,961 حديثًا) لكن النص محجوب عن العامة،
   وملفات المصدر خارج git. لا نشر قبل حقوق مكتوبة — `reports/CONTENT_LICENSE.txt`.
2. **PDF غير مدعوم** عمدًا؛ الاستخراج الآلي منه يفسد النص العربي بصمت.
3. **فصل المتن/السند** لا يحدث تلقائيًا أبدًا؛ هذه الطبعة لا تفصلهما فكلاهما `NULL`
   في كل السجلات، و`raw_text` هو المرجع.
3.ب **لا ترقيم للأحاديث في هذه الطبعة**: `hadith_number = NULL` للجميع، والهوية
   `source_locator` (مجلد/صفحة/ترتيب) — موضع لا رقم.
4. **تحديد المعدّل في الذاكرة** — يكفي نسخة واحدة؛ خلف عدّة نسخ يلزم مخزن مشترك.
5. **بناء APK وiOS محجوبان**: لا Android SDK في البيئة، وiOS يحتاج macOS وحسابًا.
   اختبارات Flutter نفسها شُغّلت (36 + 8 اختبار عقد حيّ مقابل الـAPI).
6. **بحث الترادف/الجذور** غير مدعوم: المطابقة حرفية بعد التطبيع، بلا تجذيع عربي.
7. **التحقق البشري لم يُنفَّذ**: الآلية جاهزة ومختبرة، والتحقق الآلي غطّى كل سجل
   مقابل ملف المصدر، لكن لم يقارن إنسان أي عيّنة بالمطبوع أو بالبخاري/مسلم،
   فـ`verified=false` للجميع.
7.ب **اسم الراوي مشتق آليًا** من مطلع «عن …» بقاعدة صارمة (92.4% تغطية) ولم يُراجع
   بشريًا؛ الباقي `NULL`.
8. **`corpus.hadiths_public`** يحجب النص، لكن المسار العام يمرّ عبر الخادم؛ من يستعمل
   Supabase مباشرة من عميل يجب أن يقرأ من هذا العرض لا من الجدول.

## أوامر

```bash
cd backend
npm ci
npm run db:reset          # قاعدة اختبار محلية من الهجرات
npm test                  # 145 اختبارًا
npm run verify            # تقرير سلامة البيانات (21 قاعدة)
npm run smoke             # نداء فعلي لكل نقطة نهاية (يتطلب خادمًا يعمل)
npm run dev               # تشغيل الـAPI محليًا
npm run import -- --file <ملف> --adapter jami_kamil --edition jami-kamil-1437 --dry-run
```
