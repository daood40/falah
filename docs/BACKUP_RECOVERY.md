# BACKUP_RECOVERY — النسخ والاستعادة

القاعدة: **قاعدة البيانات ليست المصدر الوحيد للحقيقة.** مجموعة القرآن قابلة
لإعادة التوليد من خط الاستيراد نفسه، وبصمة الملف المصدر مخزَّنة مع كل نسخة.

## 1. ما الذي يجب أن يُنسخ

| الأصل | أين | كيف يُستعاد |
|---|---|---|
| المخطط | `quran_api/migrations/001..006` (في git) | `npm run db:apply` |
| بيانات القرآن والبنية | مشتقّة من الحزم المثبّتة | `npm run import -- --version=…` |
| نسخ Dataset وبصماتها | `quran.quran_dataset_versions` | نسخة قاعدة البيانات |
| مركز التراخيص والأدلة | `quran.license_records` + `owner_dropzone/licenses/` | نسخة قاعدة + نسخة المجلد |
| الاعتماد البشري | `quran.human_verifications` | نسخة قاعدة البيانات |
| الأنظمة المعلنة (سجدة/صفحات) | `quran.data_schemes` | نسخة قاعدة البيانات |
| بيانات المستخدمين | جداول `user_*` | نسخة قاعدة البيانات |
| تقارير التحقق | `quran_api/reports/` (في git) | git |

**ملاحظة:** الترجمات والنص لا تُرفع إلى أي مكان عام في أي نسخة احتياطية
(القاعدة في `docs/PRIVATE_DOCUMENTATION.md`): النسخ خاصة ومشفّرة.

## 2. الحد الأدنى للنسخ

```bash
# مخطط + بيانات، بلا أسرار
pg_dump --no-owner --no-privileges --format=custom "$DATABASE_URL" > falah-$(date +%F).dump

# استعادة إلى قاعدة فارغة
createdb falah_restore
pg_restore --no-owner --dbname "$RESTORE_URL" falah-2026-09-17.dump
```

على Supabase: النسخ اليومية المدارة + PITR حسب الخطة، ولا تُعتمد وحدها.

## 3. إعادة التوليد بدل الاستعادة (الأقوى)

نص القرآن لا يحتاج نسخة احتياطية أصلًا — يُعاد بناؤه بنفس البصمة:

```bash
npm ci                       # نفس نسخ الحزم المثبّتة في package-lock.json
npm run db:apply
npm run import -- --version=<نفس النسخة> --translations=<نفس اللغات>
npm run integrity:final      # يجب أن يعطي 41/41
npm run verify:cross         # يجب أن يعطي 6,236/6,236
```

بصمة الملف المصدر المخزَّنة في `quran_dataset_versions.source_file_hash` هي
الدليل على أن ما أُعيد توليده مطابق لما كان.

## 4. اختبار الاستعادة

`npm run bootstrap:check` ينشئ قاعدة فارغة وينفّذ السلسلة كاملة (هجرات →
استيراد → تحقق → تشغيل → فحوص) ثم يحذفها. شغّله دوريًا: استعادة لم تُختبر
ليست نسخة احتياطية.

## 5. RPO / RTO المقترحان

| البيانات | RPO | RTO | السبب |
|---|---|---|---|
| القرآن والبنية | 0 | دقائق | يُعاد توليدها من المصدر بالبصمة نفسها |
| التراخيص والاعتماد البشري | 24 ساعة | ساعة | سجلات لا تُعاد بناؤها — نسخة يومية إلزامية |
| بيانات المستخدمين | 24 ساعة | ساعة | نسخة يومية |

## 6. ما لا يجوز

- الاعتماد على قاعدة إنتاج واحدة كنسخة وحيدة.
- وضع نسخة تحوي نصًا أو ترجمات في تخزين عام أو مستودع عام.
- استعادة نسخة بلا تشغيل `integrity:final` و`verify:cross` بعدها.
