# ADR-006 — تشفير Tokens الحسابات الاجتماعية بمفتاح KMS خارج القاعدة

**الحالة:** معتمد؛ يُنفَّذ مع أول Connector فعلي (مرحلة 4).

## السياق
`social_accounts` ستخزن `access_token/refresh_token`. تشفيرها بمفتاح مخزون في القاعدة
نفسها يجعل تسريب Dump كافيًا لفك كل الحسابات.

## القرار
- التشفير في السكون بمفتاح يُدار خارج القاعدة (KMS / Vault / Supabase Vault)،
  يصل للخادم عبر `TOKEN_ENCRYPTION_KEY` / `KMS_KEY_ID` (خادم فقط — الملحق ب).
- الـTokens لا تصل للـFrontend أبدًا؛ كل عمليات OAuth والنشر عبر Edge Functions
  (البنية الحالية في `socialPublisher.ts` مصممة على هذا أصلًا).

## البديل المرفوض
تشفير بمفتاح داخل القاعدة: لا يحمي من تسرب النسخ الاحتياطية.

## السبب
v2 §21 و§27.

## الأثر الحالي
لا كود Tokens في العميل اليوم (المنصات غير المهيأة ترفض بصدق `not_configured`) —
القرار يقيّد تنفيذ المرحلة 4 القادم.
