# ADR-001 — Flutter للواجهة (Android / iOS / Web) عبر هجرة مرحلية

**الحالة:** مُفعَّل — قرار صريح من المالك 2026-09-04؛ M0 منجزة في `flutter_app/` (اختبارات SOURCE_LOCK ‏12/12 في Dart).

## السياق
المنتج يعمل اليوم كـ React PWA (v1.3.0) منشورة على GitHub Pages ومغلفة بـ Capacitor
لإنتاج APK. وثيقة v2 تعتمد Flutter لتوحيد ثلاث بيئات (Android/iOS/Web) بمحرك Canvas
عالي الأداء للمحرر والفيديو.

## القرار
اعتماد Flutter كهدف نهائي للواجهة، مع **هجرة مرحلية** وليست إعادة بناء فورية:

- الـPWA الحالية تبقى **المنتج الحي** — الموقع المنشور وworkflow الـAPK وapp id
  (`app.falah.studio`) يستمرون في العمل دون انقطاع طوال فترة الهجرة.
- الـPWA مرجع **للتصميم والسلوك** (المرجع التنفيذي للمتطلبات)، لا مصدر كود يُترجم حرفيًا.
- ما لا يُعاد بناؤه إطلاقًا: مخطط قاعدة البيانات وRLS، وEdge Functions، وسياسات
  SOURCE_LOCK — كلها طبقة خلفية مشتركة بين الواجهتين.
- خطة المراحل والتفاصيل الكاملة في [`MIGRATION.md`](../../MIGRATION.md).

## البديل المرفوض
إبقاء React PWA للأبد: يظل iOS بلا حل أصيل، وأداء Canvas/الفيديو على الأجهزة الضعيفة محدود.

## السبب
منصة واحدة لثلاث بيئات + أداء رسم أعلى (v2 §27).

## الأثر الحالي
لا شيء يُهدم. أي ميزة جديدة تُبنى في الـPWA تُصمَّم بطبقة domain نقية (بلا React)
ليسهل نقل منطقها إلى Dart لاحقًا.
