# عقد البيانات — ما الملف الذي يلزم لإكمال الاستيراد

النظام كامل وجاهز؛ الناقص هو **ملف المصدر** فقط. `ketabonline.com` محجوب من بيئة
العمل (‏HTTP 403 من البروكسي) ولا يجوز تجاوز أي حماية، ولا يُفترض أن الموقع يسمح
بإعادة التوزيع. لذلك يُقدَّم الملف من صاحب المشروع.

## المطلوب

ملف واحد بأي صيغة من: `JSON` (المفضَّل) أو `CSV` أو `HTML` المنظَّم.
المخطط الملزم: `jami-kamil-v1.schema.json` في هذا المجلد.

الحد الأدنى لكل سجل: `text` (نص الحديث كما ورد حرفيًا). كل حقل آخر اختياري،
وغيابه يعني `NULL` في قاعدة البيانات — لا تخمين ولا استكمال.

## مثال أصغر ملف مقبول

```json
{
  "records": [
    { "hadith_number": "1", "volume": 1, "page": 25, "text": "…النص كما ورد حرفيًا…" }
  ]
}
```

## قواعد ملزمة على مُعدّ الملف

1. `text` منقول حرفيًا: لا تصحيح إملائي، لا إعادة صياغة، لا حذف تشكيل.
2. `matn` و`isnad` لا تُرسل إلا إذا كان المصدر نفسه يفصلهما. غير ذلك: احذفهما.
3. `grading` و`takhrij` كما وردا نصًّا؛ لا اجتهاد ولا استنتاج.
4. `hadith_number` نصّ لا رقم (لأن المصادر تستعمل «12م» و«12/2»).
5. الترميز UTF-8 بلا BOM مفضَّلًا (BOM يُزال تلقائيًا).

## الأمر بعد توفير الملف

```bash
# فحص بلا أي كتابة في قاعدة البيانات
npm run import -- --file ./data/jami-kamil.json --adapter jami_kamil \
  --edition jami-kamil-1437 --dry-run

# الاستيراد الفعلي
npm run import -- --file ./data/jami-kamil.json --adapter jami_kamil \
  --edition jami-kamil-1437 --dataset JAMI-KAMIL-1437-V1 --actor "<name>"
```

## الصيغ غير المدعومة عمدًا

`PDF`: لا يُستخرج منه نص آليًّا في هذا النظام. استخراج PDF يُنتج أخطاء صامتة في
النص العربي (تشكيل مفقود، حروف مقلوبة، أسطر مدمجة)، وتصحيحها يعني تعديل نص شرعي.
إن لم يتوفر غير PDF، يُحوَّل خارجيًا بمراجعة بشرية إلى عقد JSON أعلاه.
