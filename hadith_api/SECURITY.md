# Security — Hadith API

## نموذج الوصول

| الطبقة | الصلاحية |
|---|---|
| العام | قراءة فقط، بلا مفتاح، محدود المعدّل |
| الإداري (`/api/v1/admin/*`) | `Authorization: Bearer <ADMIN_API_KEY>` أو JWT بـ`app_metadata.corpus_role=admin` |
| قاعدة البيانات | RLS مفعّل على كل جدول؛ لا سياسة كتابة واحدة لـ`anon`/`authenticated` |

**لا يوجد مسار — عام أو إداري — يعدّل نص حديث.** التصحيح يعني `dataset_version` جديدة.

## الأسرار

لا تُوضع في أي عميل: `DATABASE_URL` · `SUPABASE_SERVICE_ROLE_KEY` · `SUPABASE_JWT_SECRET`
· `ADMIN_API_KEY` · أي مفتاح خاص.

الفحص الآلي: `npm run security:scan` — يفحص القيم السرّية في الشجرة، وملفات `.env`
المتعقَّبة، والمفاتيح الخاصة، وتسرّب أسماء الخادم إلى كود العميل، ونصّ المدوّنة، ومخرجات
البناء. أي إصابة = فشل، وCI يتوقف.

## الضوابط المطبَّقة

* ترويسات: `nosniff` · `X-Frame-Options: DENY` · `CSP: default-src 'none'` ·
  `Referrer-Policy: no-referrer` · `Permissions-Policy` · `CORP`.
* CORS: `CORS_ORIGINS` (افتراضيًا `*` للقراءة العامة فقط).
* تحديد المعدّل لكل IP مع `Retry-After`.
* تحقق صارم من المدخلات: UUID، أعداد، قوائم مغلقة، سقف `limit`، سقف جسم 64KB،
  ومعرّف طلب لا يقبل CR/LF.
* كل استعلام SQL بمعاملات — لا تركيب نصّي لأي مدخل.
* الأخطاء لا تحمل SQL ولا أثر مكدّس ولا مسارات داخلية ولا أسرارًا.
* سجل تدقيق (`corpus.audit_logs`) لكل عملية إدارية أو استيراد.

## بوابتا المحتوى

| العَلَم | الأثر |
|---|---|
| `CONTENT_LICENSE_CONFIRMED=false` | الـAPI العام يُرجع النص `null` |
| `PUBLIC_DATA_ENABLED=false` | التصدير الجماعي يُخرج بيانات وصفية بلا نصوص |

العَلَمان مستقلان: تأكيد الحقوق لا ينشر البيانات وحده.

## الإبلاغ عن ثغرة

راسل صاحب المستودع مباشرة قبل أي إفصاح عام.
