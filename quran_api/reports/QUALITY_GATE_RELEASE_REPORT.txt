5. DEFECTS FOUND BY THIS GATE AND FIXED IN THIS RUN
--------------------------------------------------------------------------------
D-1  exact search (`?exact=true`) returned HTTP 500 for every query: the count
     statement bound a parameter it did not reference. Fixed in
     src/repositories/search.ts; 1,746 search cases now pass.
D-2  a malformed percent-encoded path segment (e.g. /surahs/%d800) threw URIError
     and returned 500. Fixed in src/http/router.ts (422 validation error).
D-3  a NUL byte in a path or query value reached Postgres and returned 500.
     Fixed in src/http/router.ts and src/app.ts (422 validation error).
D-4  an oversized request body aborted mid-stream, so the client saw a connection
     reset instead of the error response. Fixed in src/http/middleware.ts (the
     remainder is drained, then 400 is returned).
D-5  quran.import_runs and quran.audit_logs had row level security enabled AND
     forced but no policy, which denies every row to service_role — the import
     pipeline could not have written its run log on a real Supabase deployment.
     Fixed by migration 007_ops_policies.sql.
D-6  a stray session setting left on a pooled connection (e.g. statement_timeout)
     made later requests on that connection fail with 500. Fixed in
     src/db/pool.ts: every request pins its own statement and idle timeouts
     inside its transaction.
Each defect now has a named regression guard in tests/gate/modules/regression.ts.
